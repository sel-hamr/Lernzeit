# The Android app: build, sign, install

The app lives in `mobile/` (Expo SDK 58). `mobile/android` is generated by `expo prebuild` and is not
committed; the release build regenerates it every time.

## What you need

- JDK 17 (`JAVA_HOME`) and the Android SDK (`ANDROID_HOME`, e.g. from Android Studio). The first build
  downloads Gradle and the NDK (about 1–2 GB).
- The signing key, outside the repo, in `%USERPROFILE%\.lernzeit-android\`:
  - `lernzeit-release.p12`: the keystore (alias `lernzeit`)
  - `keystore.env`: `LERNZEIT_KEYSTORE`, `LERNZEIT_KEYSTORE_PASSWORD`, `LERNZEIT_KEY_ALIAS`,
    `LERNZEIT_KEY_PASSWORD`

**Back up both files** (a password manager or an encrypted drive). Android only installs an update
over the app if it is signed with the same key. If the key is lost, the app must be uninstalled and
installed fresh, and its local data with it (the cloud copy stays).

### Making a new key (only once)

```powershell
keytool -genkeypair -storetype PKCS12 -keystore $env:USERPROFILE\.lernzeit-android\lernzeit-release.p12 -alias lernzeit -keyalg RSA -keysize 4096 -validity 10000 -dname "CN=Lernzeit, O=Lernzeit"
```

Then write `keystore.env` next to it with the four variables above (the same password twice for a
PKCS12 store).

## Build on EAS (recommended)

Expo's cloud builds the APK; it shows up on expo.dev (project `lernzeit` of `sel-hamri`) with an install
link and QR code. No Java, Android SDK or long-path trouble on this PC.

```powershell
cd mobile; npx eas-cli build -p android --profile preview
```

- `mobile/eas.json`: `preview` (internal install link) and `production`, both make an APK.
- Signing: `credentialsSource: local`, so EAS signs with the same keystore as the local build. It reads
  `mobile/credentials.json` (gitignored; keystore path and passwords from `keystore.env`). Keep it out
  of git.
- Sign in once with `npx eas-cli login` (your own password).

## Build on this PC

```powershell
npm run build:apk -w @lernzeit/mobile
```

The script loads the signing variables (from the environment or `keystore.env`), runs
`expo prebuild --platform android --clean`, then `gradlew assembleRelease`, and copies the APK to
`mobile/dist/lernzeit-<version>.apk`. A release build without the signing variables stops with an
error; it never falls back to the debug key (`mobile/plugins/withReleaseSigning.js`).

### Windows: paths too long

The native code of reanimated/worklets builds into very deep folders, and on Windows the build can
fail with `ninja: error: mkdir(...): No such file or directory` once a path passes 260 characters.
Build from a short drive letter instead (no admin rights needed; the mapping lasts until you remove
it or restart):

```powershell
subst L: C:\Users\sel-hamr\projects\Lernzeit
```

```powershell
cd L:\mobile; npm run build:apk
```

```powershell
subst L: /D
```

If a build already failed, delete `mobile/node_modules/react-native-worklets/android/.cxx` and
`mobile/node_modules/react-native-reanimated/android/.cxx` first.

## Version

The version comes from `mobile/package.json` (`version`). The Android `versionCode` is derived from
it in `mobile/app.config.ts`, so raise the version before each release you install over an older one.

## Install

- On a phone: copy the APK over (or share it to yourself) and open it; allow installs from that app
  once.
- With USB debugging: `adb install -r mobile/dist/lernzeit-<version>.apk` (`-r` keeps the app's data).

## Sign-in

The app signs in to the cloud at `https://lernzeit.selhamr9.workers.dev` with the owner account. A
build for another server sets `LERNZEIT_API_URL` before building (see `mobile/app.config.ts`).
